Bench — unsaved

A saved topology lives in this project’s embarch/topologies/, beside its studies, and holds which named board played which role, on which probe, plus every declared signal. Loading one never touches hardware: the signals and the dev-bench link are re-declared straight away, and each enrolment comes back as a proposal to confirm, because binding a role to a probe means reading that chip’s live hardware ID and a file on disk cannot stand in for it.

Attached probes — drag onto the Dev bench or DUT box above, or click a probe then a box

A probe and a board are separate things: this says which probe serves which role, and the board name on each box says which board type is in it. Only two probes are ever identified — the DUT's and the dev bench's — and the same probe can serve a different board tomorrow. Dropping onto a box that already holds a probe re-binds it, reading that board's identity again; that is the migration path, not a mistake.

DUT signals

A wire between two headers is invisible to software, so a signal's route can only ever be stated. Declaring is idempotent by name — re-declaring is how a route moves, and no saved study has to change, because a study names the signal and never the carrier. This tab is the only place a signal route can be declared; there is deliberately no CLI for it.

Static firmware analysis

Reads the firmware repo's own source for its GATT table — no board, no bench, nothing flashed. What it finds is an assertion about the tree: a characteristic behind a disabled Kconfig is declared here and absent from a live discovery, and the two are kept apart everywhere they meet.

Define the wire

What this study records off the link, what the link is known to carry, the protocols a step can hand it to, and the names this repo gives the bytes.

Streams — what this study records alongside its steps

A GATT notify tap gives one characteristic its own file, decoded with a layout your firmware repo declares in embarch/study-structs.toml — pick the layout, or leave it raw. Something has to subscribe to that characteristic for it to capture anything, so a monitor step must cover it. An outpost trace tap names a signal, never a carrier, so the identical saved study runs unchanged after the bench is rewired; routes are declared in the Topology tab. Any study with a monitor step also gets a full GATT transcript at streams/gatt.csv automatically — you do not declare it and it is not capped.

# Output name Signal / characteristic Decoding Record framing

Record framing is what turns "the file has bytes in it" into "these are the bytes the DUT computed a checksum over". Give a GATT tap the magic its records begin with — GWF1 as text, or 0x42 0x53 0x53 0x03 as bytes — and embarch-core finds the record boundaries and checks each record's trailing CRC-32 after the run. Leave it blank and the capture is simply not checked, which is an honest answer and not a passing one.

No taps — this study records its steps and nothing else.

Protocols — the .eap manifests this study's steps hand the link to

A RunProtocol step hands the BLE link to a declared state machine for the length of that step — a request/chunk/consume handshake that would otherwise be a dozen brittle write steps. Manifests live in <firmware-repo>/embarch/protocols/; the study carries a resolved copy, so it replays identically on a machine that is not yours. This card is read-only: what a study carries is derived from the steps that name it, never authored separately.

A board type is a shape this repo builds for — what Zephyr means by a board — not an individual piece of hardware. Saved to embarch/boards.toml, so the bench is described where the studies that run on it live. Rescan adds the targets the repo builds for; nothing it finds overwrites what you typed. Re-saving the same name edits that type.

“Builds as” is the west board target, a different thing from the physical board this record is — it is what the Study Designer’s Build card wants.

Picking a board type opens nothing and touches no hardware.

Time — one axis for everything this study did

Step bands, GATT traffic, decoded struct rows, sample strips and the trace’s own markers, on one X axis. Every position here comes from core_rx_utc_ms — embarch-core’s own receipt clock — and never from a capture’s rx_utc_ms, which in a study CSV is dev-bench uptime and is comparable with nothing outside its own tap.

one event — click it to open the row it is a cluster: more than one event in this column, so no single one is drawn placed across two clocks — good to the axis’s stated accuracy, not to a span’s microsecond marker, stamped by the DUT itself
wheel over the plot zooms at the pointer, drag pans, double-click fits

A number at a lane’s left or right edge counts events that are real and outside this window — a tap’s scope is routinely narrower than the study, and a point mark is never clamped to an edge the way a step band is, because a clamped point would be drawn at a time it was not at. A lane with a note beside it is one this chart cannot place at all, and the note says why.

Load repartition

Where the CPU's time went, per traced subject. Read the coverage line first: a repartition computed across an interval where records were dropped is not a measurement, and this capture's own losses are stated rather than smoothed over.

SubjectKindEntriesMeasured spansTotalShare of windowNot counted

Four kinds of span are left out of a total and counted in Not counted instead, because their drawn width is an extent and not a duration: one that crosses a gap, one with no closing record, one with no opening record, and one that began and ended inside a single frame — a frame is this capture's resolution, so a span inside one has no measurable length at all. Entries counts every span regardless — “this subject ran N times” survives all four doubts. Shares are of the whole window and deliberately do not sum to 100%: an ISR runs inside whatever it interrupted, and Zephyr's idle thread is reported both as a thread and as idle records.

Gaps — what was lost, and where
FromToRecords lostRow

A gap band is a bound, not a measurement. A gap record is always the first record of the frame that reports it, so the losses happened somewhere between the previous frame's arrival and that one's — From and To are those two arrivals. A gap band is not an empty interval either: the records at both its edges survived and are still drawn.
